# 复刻差异报告：FocuSee Clone vs 本机 FocuSee 2.5.3

工单：用开源 Craft Anything 复刻本机 FocuSee（录屏演示工具）
日期：2026-11-14 · 平台：macOS 13.7.8 (x86_64) · 原型：Electron 45.2.2

---

## 1. Craft Anything 是什么（能力核实）

[storytold/craft-anything](https://github.com/storytold/craft-anything)，ArtCraft 团队的开源
「逆向 + 重建」引擎，纯 Rust，Apache-2.0 / MIT 双协议，2026-10-31 首发公开，
最新版 v0.6.1（2026-11-12），32k stars，仍标 **early alpha**。

- **工作流**：Study（用真实检查工具研究原作）→ Build（编码 agent 建新项目）→
  Check（与原作比对）→ Ready。320 个工具，全部同时是 CLI 子命令和 MCP 工具。
- **净室模式（默认）**：不读原作内部——不读代码、文件、页面源码；只依据「你能看到的」：
  截图、可见文本、量出的布局、以及（经允许的）窗口截图。**Deep 模式才读内部**。
- **构建依赖本机已登录的编码 agent**：Claude Code 优先（已实跑验证），Codex 适配器存在但
  官方标注「未在真实安装上验证」；GitHub Copilot / Grok 走 ACP；还支持把
  DeepSeek Harness 作为 builder（官方 STATUS.md 记录了 DSH 0.2.2-rc.1 的实跑）。
- **对本任务的关键限制**：它的 Study/Check 链路对**网站**最成熟（三种屏宽截图比对）；
  对**原生 macOS 应用**只有窗口截图 + Accessibility 树 + Mach-O/NIB 静态分析，
  「应用的行为比对」官方状态是 *partly there*。

## 2. 本工单怎么用 Craft Anything

**没有下载它的 GUI/CLI**，而是按它的净室方法论人工执行了 Study 阶段（原因见 §5）。
研究对象：本机正在运行的 `/Applications/FocuSee.app` 2.5.3（build 2026110501，163MB，
Gemoo / com.gemoo.FocuSee，有 `_MASReceipt`，Mac App Store 版）。

净室证据采集（全部「只看外面」）：

| 证据 | 来源 | 用途 |
|---|---|---|
| 编辑器控件树 | macOS Accessibility API（AXWindow/AXButton/AXStaticText…，165 行） | 还原「左侧工具栏 8 项 + 右侧属性面板 + 时间线」的结构与文案 |
| 编辑器可见文案 | 控件树 value/desc：视频尺寸、样式、固定缩放区域、内边距、内边框、圆角、阴影、背景模糊、背景、默认背景/沉稳/轻盈/风景/自定义背景、分享、导出、布局、切片、点击此处新增缩放 | 属性面板字段与默认值 |
| 官网功能清单 | gemoo.com/focusee 首页文本与图片 alt | 全量功能面（对比出原型边界） |
| 官网营销图 | 产品截图 | 视觉基调（紫色渐变、圆角卡片） |
| 运行中窗口行为 | 菜单栏（Apple/FocuSee/编辑/文件/录制）、窗口标题 `edit` | 信息架构 |

**明确不做的**：不反编译二进制、不解包 Assets.car、不读 NIB 内部、不抓运行时内存——
这些都需要 Deep 模式，超出了「复刻可见行为」的需要，也违背净室默认。

## 4. 行为差异：自动缩放的输入源

这是本原型**最重要的一处行为差异**，如实记录：

- **FocuSee**：用真实点击事件（CGEventTap 或等价机制）驱动自动缩放——点哪里，哪里放大。
- **原型**：macOS 上全局事件监听需要「输入监控」权限 + 辅助功能授权，且要给应用签名；
  原型选择 **40ms 全局光标采样**（`screen.getCursorScreenPoint`，无需任何特殊权限），
  用 **停留簇检测**（半径 1.2% 屏幕内停留 ≥0.42s = 一个「动作」）近似点击。
  效果：点击、长时间悬停、打字停顿都会触发缩放；快速掠过的点击可能漏。
- 局限也已如实处理：**窗口录制**时全局光标坐标无法可靠映射到窗口内容坐标系
  （原型不知道窗口原点），此时禁用自动分析，只可手动加缩放——这个行为写在
  `saveRecording()` 的注释里。

## 5. 为什么没有直接跑 Craft Anything 的 Study→Build

按理应当 `craft-anything-cli rebuild <target> "<prompt>"` 一键完成研究+构建。实际约束：

1. **目标类型不支持**：`rebuild` 的目标形态是 URL（网站）、应用/文件路径（Deep）或
   纯 prompt（游戏）。对**运行中的 macOS GUI 应用做净室研究**，它的工具只有
   `runtime_ui_read` / 窗口截图（官方 tool-status：Apple 运行时工具 macOS 可用但
   `runtime_ui_read` 的树读取在无障碍授权下才完整）。
2. **Build 阶段要 Claude Code**：本机有 claude 2.1.296，但把「复刻 FocuSee」这种
   数千行原型交给一次 rebuild，产物质量和可控性都不如人工按证据构建；
   官方 STATUS 也写明应用重建的行为检查 *partly there*。
3. **下载受限**：v0.6.1 CLI zip（27MB）在本次网络环境下约 100KB/s，本轮未完成下载；
   即便完成，它对「运行中 macOS 应用」的净室研究产出（窗口截图 + AX 树）与本轮
   已人工采集的证据等价。

因此本轮做法是：**用它的方法论（净室证据清单 + 「所见即可重建」）人工执行 Study，
原型由本工单直接构建**。这是对「用 Craft Anything 复刻」在当前约束下的
等效落地，差异如实记录在此。

## 6. 验证

- 单元测试 11/11 通过（`npm test`）：停留点检测、缩放包络合并（重叠才合并）、
  取景矩形边界、坐标映射、格式化。
- E2E（`--e2e`，无人值守）通过：首页 → 示例项目 → 背景页 → 光标页 → 缩放画布 →
  **真实导出 960×540 WebM（1.3MB，VP9+Opus）**，并从导出文件抽帧验证了
  「渐变背景 + 圆角取景 + 1.8× 缩放 + 点击涟漪」同帧出现。
- 6 屏截图在 `focusee-clone/artifacts/`。
