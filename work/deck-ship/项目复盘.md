# 项目复盘 — deck-ship 交付强制链（工单 deck-ship-enforce-860f53caf540）

复盘时间：2026-11-14 01:35（Asia/Shanghai）
评价标准：**交付路径上"跑不跑不由人"**——检查工具只有在"不跑就发不了货"时才算机制。

## 一、最终事实

- **问题**：deck-lint / cite-check 已建成并实测，但无 hook、build 未调用，交付靠记性；用户原话
  "检查自动化了，强制还没落地——严格讲，还不算机制化"。
- **落地**：
  - `~/.local/bin/deck-ship`：lint 0 FAIL + 字体白名单 + cite 门禁全过才原子复制；写
    `<stem>.ship-manifest.json`（文件哈希/gate 计数/来源哈希）；被拦 exit 1、交付目录不变。
  - 项目 `work/build/ship_d.sh`：build → render → lint/cite → ship 一条链，退出码即"能不能发货"。
  - `work/build/build_d.py` 保存后自动 deck-lint，FAIL 则构建失败。
  - cite 三源（期刊 OCR + 原稿文本 + 化验单转写表）+ 5 条带原因的派生值白名单。
  - 自测：工具 13 项（正/负/blocked-means-empty/verify-only）+ 项目 `ship_d_selftest.sh` e2e。
- **验证**：全链 SHIPPED（2 文件 + manifest，lint 0 fail / 2 warn，cite 98 claims / 5 allowed /
  0 blocking）；`--expect 17` → BLOCKED（exit 1，交付目录 0 文件）；无源数字 → BLOCKED；字体白名单
  拦 QA 构建；既有交付 `--verify-only` = VERIFIED。
- **规模**：新增工具 1 个（约 500 行）、patched 2 个检查器、项目链 1 个、build 门禁 1 处、
  语料 3 份、自测 13 + 5 项。
- **遗留**：非宿主 hook（不能物理阻止手工 cp）；cite 为字符串级（12h 为 OCR 误识，白名单待人工按
  PDF 核）；项目 `ship_d.sh` 的文本 dump 未含 pptx 表格（当前稿无表格，后续加表需改用它或换
  `deck_text.py`）。

## 二、做得对的

1. **先读现有工具再动手**：复用了 deck-lint / cite-check，只补 `--json` / `--fail-on-missing`，
   没有另写一套检查器。
2. **门禁 fail-closed**：白名单无原因直接判 gate 错误；缺工具/缺语料时阻塞而不是降级。
3. **blocked-means-empty 写进自测**：每次负测试都断言目标目录 0 文件，而不是只看退出码。
4. **原子写入**：临时文件 + sha256 校验 + `os.replace`，失败不留半成品。
5. **manifest 作为交付凭据**：哈希、gate 计数、语料哈希都可复核，后续会话不用信"我记得跑过"。
6. **发现并发覆盖后不掩盖**：定位到另一会话的 symlink 覆盖导致假失败，恢复后复跑并记录（E138）。

## 三、犯过的错

1. **`exec > >(tee)` 日志竞态**：第一版 ship_d.sh 用进程替换写日志，自测在脚本退出后立刻 grep
   日志，读不到末尾几行（假失败）。改为每个命令同步 `| tee -a`，退出码用 `PIPESTATUS`。
2. **verify-only 子集覆盖 manifest**：只传 deck 做 verify 会把已记录的 PDF 从 manifest 中丢掉；
   已修成"保留并按记录哈希复核未传入的文件"。
3. **并发工单共享路径未先查**：`~/.local/bin/deck-ship`、项目 `ship_d.sh` 被另一会话覆盖，
   浪费一次 e2e 排查。动了共享入口前应先 `readlink` / 看 mtime / 看日志（E138）。

## 四、如果重来会怎么做

1. 先把"交付唯一入口"定下来再写工具；入口定了，门禁/自测/文档才有落点。
2. 共享路径（`~/.local/bin/*`、项目脚本）动手前查并发：`readlink`、mtime、`ps`、最近日志。
3. 自测从一开始就断言"目标目录为空"，而不是只断言退出码。
4. cite 语料第一版就建"事实表"（含图片型报告的转写），而不是逐条补白名单。

## 五、仍未解决

1. 非 hook：手工 `cp` 物理上拦不住，靠 build 门禁 + AGENTS 规则 + manifest 可核验。
2. `12h` 原文 OCR 误识（`6~)121`），白名单已注明待人工按 PDF 原文核对。
3. 项目 `ship_d.sh` 的内联文本 dump 未含表格；如后续稿子使用 pptx 表格，应改用 `deck_text.py`
   或补表格提取。
4. 交付 PDF 用 Heiti SC QA 构建渲染（macOS LibreOffice 缺微软雅黑），与 pptx 字体声明不同。
