## 三、犯过的错（每条附可推翻证据）

1. **被无头 Chrome 的幽灵 AX 窗口误导**：osascript 报窗口 (0,25,1680×991) 未最小化、标签「验证码中间页」，据此让用户去找窗口，用户两轮说看不到，浪费往返。根因：`--headless=new` 的 Chrome 在 System Events 仍暴露 AX 窗口几何，我先指路后验证。
   *可推翻证据*：若截屏里能看到 douyin 窗口被 Space 遮挡，则归因应改为 Space/遮挡——但 22:03 截屏实际是用户主 Chrome，证实该窗口不存在。
2. **默认相信日志「切有头重试」语义，且一度推断错方向**：最初以为「有头重试」= 用户可见窗口仍被拦；读源码定案：`relaunch_chrome(headless=False)` 确实去掉 `--headless=new` 但加 **`--start-minimized`**（v0.2.5 用户拍板防窗口闪现）——有头重试是真实窗口但**最小化**，人工过验证必须先点 Dock 图标展开，这正是「重新登录」路线多绕一轮的原因。另：今晚报错串 `captcha+relaunch` = relaunch_chrome 返回 False（90s 内 CDP 端口未就绪，属「有头重启失败」），并非「有头可见仍被拦」——两条失败路径的通知文案不同，当时未区分。
   *可推翻证据*：若后续复现时有头窗口实际弹出且被拦（错误串应为 `captcha+headed retry`），则本条对今晚失败路径的归类需修正。
3. **docker.sock 消失时排查方向偏了**：先怀疑 colima 没起来，挂着一个后台 job 等了 ~14 分钟；实际 colima 正常，是 /var/run 软链被重启清掉，LESSONS E121 早有⑥步记录但「不持久」属性未记载。
   *可推翻证据*：若 docker daemon 确实未随 colima 启动（再等会自己好），软链归因不成立——但 DOCKER_HOST 直指 colima socket 后立即成功，反向证实 daemon 正常。
4. **GitHub 推送排障漏掉代理变量**：推送被间歇重置时我先得出「GitHub 双通道中断」的过强结论，反复重试烧了 ~25 分钟；用户一句「github 明明可用啊」点破——浏览器走 Clash 代理所以一直可用，我的 git/gh 命令在裸连。对照「浏览器可用 vs 命令行不通」时第一步就该查代理路径差异（Clash 7890 就写在 dysub config 里）。终态：SSH 走 Clash socks5 认证成功并把 `core.sshCommand` 走代理写进仓库配置持久化；推送因当晚网络窗口仍未完成，挂明日待办。
   *可推翻证据*：若当晚裸连 git push 曾稳定成功过（而非间歇通），则「间歇阻断」归因不成立——但 6+ 次失败与 2 次成功（一次 https API 建仓、一次 SSL 失败）交替的日志支持间歇判定。
