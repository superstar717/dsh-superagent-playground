- **PC 侧落地（2026-11-21 当天完成）**：PC-20230915XMXX（Win10 Pro 19045，Tailscale 100.80.147.68）

  administrator SSH 公钥；全部经 SSH 命令实测（tree/net share/ACL/本机 net use 回环验证）。

  PC 删除任务后缓存同步清理；fetch 端到端秒级。

## 三、做得对的

1. **先查存量结论**（AGENTS §十一）：开工先检索群历史与仓库文档，确认 11-17 的「12–16G/云端」口径并对齐，
   避免了第三份互相矛盾的可行性叙事。
2. **数字全部挂标签**：官方/社区/本机/估算四类来源标签贯穿文档，估算值（提速倍数、渲染耗时预测）显式声明
   且给出替换方法（跑基准）。
3. **通道切换果断**：SMB 首次 IO 挂死后没有反复调参硬磕，6 秒 watchdog 判死 → 换已验证秒回的 SSH 通道，
   架构从「挂载共享」降级为「拉取缓存」仍满足原始需求（长任务随时可见）。
4. **mock 全链路验证后才报 ready**：fetch/看板/清理三个环节都用临时任务实测，而不是「脚本写完=能用」。
5. **教训查重后落档**：E194 命中即更新原条目（不新增重复），E201/E202 查无重复才追加。

## 四、犯过的错（每条附「什么证据能推翻该归因」）

1. **漏了操作面盘点，先答「无法操作 PC」**——本机 Tailscale 有 PC 节点、known_hosts 里有主机键，
   用户一句「你可以操作PC」后才盘点出 SSH 通道。可推翻证据：若盘点当时发现 SSH 需要密码/无密钥授权，
   则「先答不行」是正确结论；实测 BatchMode 一次连通，归因「未盘点而非做不到」成立。
2. **在 fork 上开了 PR #50**，触发工单绑定校验失败后 close+重建（#51）——开 PR 前未读宿主绑定规则
   （分支须在被监听仓库）。可推翻证据：若 gh-agent wrapper 当时给了重叠/位置警告而忽略，归因改为「忽视警告」；
   实测 wrapper 未提示绑定约束，归因「规则未知、未先查」成立。成本：一次重复 PR + 一条说明评论。
3. **在 SMB 上耗了约 40 分钟**（挂载死锁、umount 卡死、multichannel/踢会话尝试）才彻底换道。
   可推翻证据：若存在任一次成功目录 IO，则「SMB 经 Tailscale 可用、首次失败是偶发」成立、换道过早；
   实测全程零成功 IO，归因「通道本质不可用」成立。
4. **SSH→PowerShell stdin 静默失败浪费 2 轮**（跨行 foreach 被打碎不执行、无报错）——E194 已有
   「复杂 PS 一律落文件/EncodedCommand」的预防但未先检索命中（静默无输出不触发报错检索，属第五节的灰色地带）。
   可推翻证据：若 E194 写入时间晚于本工单踩坑时刻，则「教训尚不存在」成立；实测 E194 落档早于本次踩坑
   （同为 11-21 但 pc-setup-continue 工单在前），归因「既有教训未检索到」成立，已把 stdin 变体补进 E194。

## 五、时间/效率估算的依据

- 「一条 27s 成片现状 30–45 分钟」= 本机实测两段相加（配音 RTF 13–24 × 10 句 = 17–27 分钟；渲染 10–15 分钟
  来自 motiongit README 实测记录），**不是**对 PC 的预测。
- 「一期后 12–18 分钟 / 二期后 5–8 分钟」= 上述两段分别被估算值替换后的算术，**估算**（GPU 提速倍数未实测），
  文档已要求以 10 句配音基准替换。
- 「sftp 往返 1.3s / fetch 端到端秒级」= 当日 `time` 实测。
- SMB 折腾 40 分钟 = 会话时间戳区间（19:55 首次挂载成功至 20:05 放弃换道），**按时间戳推断的投入时长**，
  不代表等价工作量。

## 六、如果重来（推荐顺序）

1. **开工先做「操作面盘点」**：本机能碰哪些机器、什么通道（SSH/Tailscale/共享），再回答「能不能做」——
   第 1 次回答「做不到/需要你操作」前必须先盘点，这条已值得沉淀为通用开工步骤。
2. 对 PC 的任何复杂命令直接 `-EncodedCommand` 或 `.ps1` 文件，不试 stdin 通道（E194/E202）。
3. 挂载类方案先跑 6 秒 IO watchdog 再宣布可用（E201）；watchdog 挂死立即评估替代通道，不做第三次调参。
4. 分支/PR 先确认宿主绑定规则（分支在被监听仓库）再创建，避免 fork 返工。
5. 复盘与教训本可在换道 SSH 的当天随手落档（实际已做），但「操作面盘点」若开工就有，可省去第 §四-1 的返工。
