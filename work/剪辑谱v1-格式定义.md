# 剪辑谱 v1 · 格式定义与执行器

> 工单：edit-score-pipeline-430f781bffe8（复刻主播剪辑思路 · 垂直切片）
> 日期：2026-11-24　|　状态：**样本验证通过**（谱 → 执行器 → 与已交付成片三项产物全 MATCH + 视频 PSNR 见验证报告）

## 一、剪辑谱是什么

**剪辑谱 = 一条视频的剪辑决策的声明式描述**（JSON），把「怎么剪、为什么这么剪」从管线代码和人的记忆里解耦出来：

- **谱（score.json）**：声明 what & why —— 保哪些段（含 beat 归属）、删哪些区间（含归因：重复句/停顿/重启）、特效放在哪（含理由）、字幕规格、渲染参数、验收口径。
- **执行器（score_executor.py）**：通用实现 how —— 照谱产出 plan/effects/ASS 并驱动 ffmpeg 渲染。**换视频只换谱，不改执行器。**

一页谱对应五维拆解（源自知识库方法卡：姜胡说短视频系统 / 口播剪辑五技巧 / 王者拍摄法）：

| 五维 | 谱字段 | 可量化 |
|---|---|---|
| 结构 | `beats[]`（role: hook/context/inciting/backstory/turn/action/conflict/reversal/payoff/close + 源区间 + 依据） | ✅ |
| 节奏 | `keep[]`（输出顺序段表）+ `edits[]`（删除区间+归因+规则）+ `rhythm_stats`（切点间隔统计） | ✅ |
| 字幕 | `subtitle`（样式/断句规则/专名修正/存疑词） | ✅ |
| 画面证据 | `effects.callouts[]`（花字）+ `effects.zoom[]`（推拉强调）；B-roll 素材清单由 beats.note + whoosh_joins.note 记录 | ✅ |
| 情绪/包装 | `effects.whoosh_joins[]`（转场音效）、`effects.fades`、`audio.bgm` | 半可量化（位置可量化，选择靠人/AI） |

## 二、谱文件字段（edit-score/v1）

| 字段 | 内容 | 执行器用法 |
|---|---|---|
| `meta` | 源片路径/时长/分辨率/帧率、交付成片引用、真值引用 | 源片与规格输入 |
| `beats[]` | 结构 beat：id/role/src/note | 文档层，不驱动渲染 |
| `keep[]` | 输出顺序的保留段（src + beats 引用 + note）；**钩子倒挂 = 输出顺序第一位**，不靠源时间 | 直接产出 plan.segments |
| `edits[]` | 删除区间：type（repeat/restart/pause_tighten/lead_in/tail）+ note + rule；repeat/restart 做整词校验（±0.02s） | 开工校验，VALID=FAIL 不渲染 |
| `effects.zoom` | factor + 源时间区间列表 + expected_out（交付时刻自检） | 重映射为输出时间 → overlay |
| `effects.callouts[]` | 花字文本 + 源时间 + expected_out | 重映射 → ASS Callout 事件 |
| `effects.whoosh_joins[]` | 输出时间 + 理由 | adelay 置 join 前 150ms |
| `effects.fades` | 首淡入/尾淡出/音频尾淡出 | fade/afade |
| `subtitle` | playres、font_stack（跨平台回退）、styles、line_rules（max_len/max_gap/min_dur/切点断句/±80ms 边界容差）、fixes、open_questions、`burn`（可选，默认 true；源片已带烧录字幕时置 false——ASS 产物照常生成供比对，渲染不二次压字） | 生成 ASS；burn=false 时跳过 ass 滤镜 |
| `audio` | join 交叉淡化 8ms、whoosh 配方、bgm 配方（status 标记 pending_user_file） | pass1 淡化 + pass2 amix |
| `render` | 编码器/crf/preset/音频/zoom 裁切参数 | ffmpeg 参数 |
| `rhythm_stats` | join 输出时刻、段长、平均切点间隔 | 文档层 |
| `acceptance` | expected_duration + 容差 + 检查清单 + open_items | 渲染后自动时长对账 |

**设计约束**：谱里所有时刻分两类——`keep/edits/特效 src` 用**源时间**（可迁移、可对词），`whoosh_joins/expected_out` 用**输出时间**（自检锚点）。源→输出重映射由执行器完成（与交付管线同一算法）。

## 三、执行器

`work/score_executor.py`（stdlib，Python 3.8+，Mac/PC 通用）：

```bash
# 校验 + 产物比对（不渲染）
python3 score_executor.py --score S.json --source SRC.mp4 --transcript T.json \
    --work OUT --reference-plan plan2.json --reference-effects effects.json --reference-ass final2.ass
# 完整渲染 + 时长对账 + 抽帧 + 与交付成片整片 PSNR
python3 score_executor.py ... --render --font "Microsoft Ya Hei" --compare final2.mp4
```

执行器内置三道保真闸（对有交付真值的片子）：
1. **整词校验**：repeat/restart 删除区间内的词必须完整落界（沿用交付管线规则）；
2. **重映射自检**：特效 remap 结果必须命中谱内 `expected_out`；
3. **真值比对**：plan 段表 / effects 窗口 / ASS 全文与交付真值逐一比对（ASS 要求逐字节一致）。

## 四、从一条已交付片子「谱化」的流程（本样本即此路径）

1. 真值收集：交付管线（plan/effects/ass/transcript/silence）→ `work/groundtruth/`；
2. 逆向标注：段表 → `keep[]`；删除区间 → `edits[]`（归因从 build 脚本注释+silence.log 交叉）；特效源时刻 ← build 脚本 win() 入参；字幕样式 ← ASS header；断句规则 ← build_subs 常量；
3. 写谱：填 `expected_out`（交付 effects.json 值）作为自检锚点；
4. 执行器校验：三项 MATCH 才算谱化成功；
5. （可选）重渲染对账：同环境渲染 → 时长/PSNR/抽帧比对。

## 五、复刻到下一部片子的路径（谱的真正用途）

| 步骤 | 复用 | 新增工作 |
|---|---|---|
| 对词 | SenseVoice（RTF≈0.12）/ PC faster-whisper | 换源片重转写 |
| 摸底 | ffmpeg silencedetect + 场景检测 | 新静音表/镜头表 |
| 拆谱 | **本格式 + 执行器不变** | AI/人从逐字稿切 beat、选钩子、标重复句、定花字/推拉/音效位 |
| 执行 | score_executor 全套（词边界校验→重映射→ASS→两 pass 渲染→对账） | 仅换谱文件与源片 |
| 验收 | acceptance.checks 模板 | 填新 expected_duration |

即：**方法论沉淀在谱格式里，工程能力沉淀在执行器里，一部片子只是一份谱。**

## 五·二、正向产谱路径（2026-11-24 EP05 样本已走通，详见《验证-正向产谱-EP05-2026-11-24.md》）

对词→beat→谱→执行器复现→三层比对（beat vs 独立模块表 / 字幕行 vs 作者字幕卡 / 渲染 vs 原片）。
本样本（一只桌子 EP05，教程片/横屏/无切点）实测：**换体裁只换谱不改执行器**成立；对词层（词级时间戳）
与节奏层（声学停顿=章节边界）可机械迁移，字幕断句粒度是主播个人参数（应写进谱 `line_rules`）。
 QC 抽帧时刻亦改为谱可控（`acceptance.qc_frames`，缺省回退旧默认）。

## 六、边界（诚实声明）

- 谱是**约束与执行**层；钩子选哪句、花字写什么词、推拉放哪，目前仍由人/AI 判断（逆向样本的谱化对象是已交付成片，决策已存在，逆向标注 ≠ 自动决策）。AI 直接产谱（对词→beat→谱）已于 2026-11-24 在 EP05 样本上首跑：beat 边界与对词层可正向生成并与独立参考 11/12 对齐（±4s），字幕行时刻 97% 踩点作者卡；**选钩子/花字文案类创意决策在教程片样本中未触发**（effects 全空是本片正确决策），该能力仍未被验证。
- BGM 混音、拼接点人工听感、抠像等 open_items 原样保留在 `acceptance.open_items`，谱不假装它们已解决。
- 竖屏真人短视频的五维里，「画面证据」（B-roll 插入/分屏）口播样本只有录屏切换一个；EP05（动画+录屏混编）补了第二类样本（章节卡/黑场过渡/IP 形象插入），B-roll 仍靠场景检测+抽帧人工读画，无自动打标。
