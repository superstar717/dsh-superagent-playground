## 一、最终事实

- **现象**：用户浏览器访问 `http://127.0.0.1:3082/` 得纯文本 401
  `dsh web authentication required; reopen the URL printed by 'dsh web'`；用户问重新登录是否会好。
- **结论**：**会好，且已代为执行**。401 = 浏览器对该 host:port 没有有效 `dsh-auth-*` cookie；
  登录 token 每次宿主重启都会轮换，旧链接一律 401。已用 `dsh-web-open` 打开当前链接完成重登（rc=0）。
- **机制（官方源码佐证）**：`deepseek-harness` checkout
  `packages/client/connection/src/browser-auth.ts` —— 每进程一枚 launch token（重启即换）；
  `GET /?token=<token>` 换发 30 天签名 cookie（HttpOnly、SameSite=Strict）；cookie HMAC 密钥持久于
  `~/.dsh/.credentials.yaml`（`client-connection/browser-session`，绑 host:port），同端口重启旧 cookie 仍有效。
- **验证状态（全部实测，2026-11-21 21:40–21:46，curl 全链路）**：
  | # | 实验 | 结果 |
  |---|---|---|
  | 1 | 无 cookie `GET /`（基线） | 401（复现用户症状） |
  | 2 | 历史重启的旧 token 链接 ×2（uJknyz… / B0Lyud…） | 均 401（旧链接失效证实） |
  | 3 | 当前 token 链接（wS71c…，19:45 启动的进程） | 303 + Set-Cookie（30 天，至 2026-12-21） |
  | 4 | 带 cookie `GET /` | 200（会话有效） |
  | 5 | 同一 token 链接再次打开 | 303（可重开、非一次性；多浏览器各自换发互不排斥） |
  | 6 | `dsh-web-open`（打开） / `--print` | rc=0 / 输出与日志一致的当前链接；服务端复检 303 |
