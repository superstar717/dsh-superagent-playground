### 9.3 犯过的错（每条附「什么证据能推翻该归因」）

1. **ETA 公式单位混用（MB/s 当 bytes/s），首版日志出现 ETA 53873861 min**
   - 归因：`rate` 已除 1e6 换成 MB/s，却仍按 bytes 计算剩余时间。
   - 可推翻证据：若首版日志 ETA 数值量级正常（几十~几十分钟），则归因不成立；实测首版两行均为 53,873,861 / 53,459,616 分钟级大数。
   - 处置：重启任务（续传）后修复，损失 4 秒与 0 字节。
2. **首次把 Python 装在 Store 版 venv 上跑 SYSTEM 任务，白跑一轮（EXITCODE=101）**
   - 归因：默认「venv 里的 python.exe 就是独立解释器」，未查 `pyvenv.cfg` 的 `home`。
   - 可推翻证据：若 `pyvenv.cfg` 的 `home` 指向 `C:\Program Files\Python*`（非 WindowsApps），则归因不成立；实测指向 WindowsApps。
3. **监控脚本首版无停滞检测，若下载静默死掉会空等数小时**
   - 归因：只按完成/失败标记退出，没有「连续 N 周期无增长」判定。
   - 可推翻证据：若首版脚本含 stall 判定则归因不成立；首版 `monitor_download.sh` 无该逻辑（第二版才有）。
