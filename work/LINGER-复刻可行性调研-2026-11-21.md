## 0. 一页速览

**这篇报道讲的是一个"跑在自己电脑上的个人 Agent"：Linger（Simplex AI，张博/Tony Zhang，前 DeepSeek-VL 负责人）。它的差异化不是模型本身，而是四件事的组合：**

1. **宿主优先**：Agent 直接住在你的 PC 上，用你已登录的浏览器/邮件/日历/Slack，不需要重新配置凭据；
2. **双层记忆**：个人 Wiki（按客户/联系人/项目/主题/会议建 typed Markdown 页，每晚 00:00 重写并留 change log）+ 每个 Agent 自己的 memory；
3. **主动性 + 隐式强化**：轮询邮件/日历/Slack，按重要/紧急决定是否打扰；用户对提醒的反馈每晚被蒸馏成规则（"供应商发票→立即提醒"）；
4. **模型-宿主协同设计**：自研 MoE 分层推理引擎 PolyStrata（基于开源 Strata），把冷专家放内存/SSD，12GB 显存跑 125B 的 Qwen3.8-Flash-Next，官方称 45.5 tok/s。

**结论（三档复刻，推荐第 2 档）：**

| 档位 | 目标 | 可行性 | 最小路径 | 工作量/成本 |
|---|---|---|---|---|
| A「用上」 | 装 Linger 本体 | **本机不行**：桌面版仅 macOS 14+ Apple Silicon / Win x64 / Linux x64，官方明确"Intel Mac 无包，只能用 Docker Compose 跑服务端" | 借/买一台受支持机器，或用 BYOK 云模型 | 0 代码；1 天安装 + 1 晚观察；硬件成本另计 |
| **B「复刻体验」（推荐）** | 在现有 DSH 值守栈上补齐 Linger 的三块能力：夜间 Wiki、主动 watcher、桌面接管 | **可做**，本机 macOS + DSH 已具备 70% 底座；缺的是 wiki 流水线、主动调度、Cua 级桌面控制 | P1 夜间 Wiki（1 周）→ P2 主动 watcher + 规则（1 周）→ P3 桌面接管（2–3 周） | 单人 + agent 协作约 4–6 周（[估算]）；0 新增云成本 |
| C「复刻产品」 | 做一个 Linger 同类产品 | **不建议从零**：Linger 本身 ≈ 110 万行、8 个主要模块、1652 个测试文件、686 commits、18 位贡献者、发布 11 天 | fork Linger（许可证允许自用/商用，禁托管服务、禁去 LOGO）或"DSH harness + 自研 shell + PolyStrata/Strata"组合 | ≥6 人月才到"可用"（[估算]，见 §4.3） |

**一句话建议**：你的工作数据主要在飞书，而 Linger 的连接器只覆盖 Gmail / Outlook / Slack / Notion / GitHub / Google·Outlook 日历 / Drive——**没有飞书**。所以"复刻"最划算的形态不是装 Linger，而是**把 Linger 的交互范式（夜间个人 Wiki + 主动提醒 + 规则学习）搬到现有 DSH + 飞书栈上**；Linger 本体的价值是"参考实现 + 本地推理引擎"，等你有 NVIDIA 12GB 机器或 Apple Silicon Mac 再直接装来对照。

## 1. 原文思路拆解（它到底新在哪）

原报道是量子位的产品发布稿（含营销语气），核心主张可拆成 6 条：

1. **PC 优先，不是 App 优先**
   > "当同行都在做 APP，他们优先选择了电脑。这意味着，Linger 能操纵你电脑已有的网页、邮件箱、日历，无需折腾一大堆登录凭据。遇到卡住的地方，你也可以直接上手接管。"

2. **记忆中枢「Another Me」**
   > "Linger 会在本地读取你的收件箱、日历、聊天记录和会议，每晚自动将这些信息整理成个人知识库（Wiki），供所有 Agent 查询。"
   > "在衡量长期对话记忆能力的 LoCoMo 基准测试中，Linger 的准确率达到了 95%，超过了 Mem0、MemOS 等多个记忆增强型 AI 系统。"

3. **主动 + 隐式强化**
   > "它会默默观察你的信息流，根据事件的重要性和紧急性决定何时提醒你……如果下一次另一张发票出现类似情况，你再次表达了相同的偏好，系统就会自动生成一条规则：'供应商发票→立即提醒'。"

4. **模型与 harness 共同优化（本地推理）**
   > "一块 12GB 显存的 RTX 3060 显卡，就能跑起一个 125B 参数的 Qwen3.8-Flash-Next，并且是 45.5 tokens/秒的生成速度。"
   > "Tony Zhang 回应：Linger 的重点是把模型和 harness 一起优化：12GB 显卡就能本地跑 125B 模型，不按 token 付费，数据也不出本机。"

5. **中间层：可接第三方模型**
   > "作为中间层的 Linger，支持接入各个第三方模型。并且专门为本地 LLM 做了优化。"

6. **Agent 团队 / 任务委派 / 语音**
   > "你下达一个复杂任务时，Another Me 会调用或创建不同职能的 Agent，协同完成工作。而你，只用停留在和 Linger 这一个 Session。"
   > "Linger 能实时转录会议，会后直接向 Agent 提问会议内容，并让它跟进待办事项。"

**它真正的不一样**：市面上"个人 Agent"多数是"聊天框 + 工具调用 + 向量记忆"；Linger 把**记忆做成可读可改的实体化 Wiki**（客户/联系人/项目/主题/会议各一页），把**主动性做成有规则、可解释、可回滚的策略**（每晚 rewrite rules，不重训模型），再用**本地 MoE 分层推理**把"数据不出本机 + 零 token 费"落到消费级硬件上。三者叠加才是它的"思路"。

## 3. Linger 到底是什么（架构与规模）

### 3.1 架构（官方 `docs/architecture.md` 转述）

```
Web (React 19 + Vite + BlockNote)
  │  Yjs WebSocket / HTTP+SSE
  ├── node-services（Node 26 + Hono）：Agent Service、Document Runtime、Memory、LLM Wiki
  ├── TeamHub（Go + Gin + PostgreSQL 17 + River 队列）：Rooms、Documents、权限、任务
  └── Voice Runtime（LiveKit + Soniox ASR + FFmpeg）

Computer Daemon（Go + SQLite）——每台电脑一个后台进程，只出站 WebSocket
  ├── Runtime adapters：Codex app-server / Claude stream-json / Pi RPC / Antigravity ACP
  ├── Agent workspace：playground/ 可写，agent/ 是它自己的 npm+uv 工程，memory/、llm-wiki/ 只读
  ├── LLM Gateway：本机或远程模型（BYOK）
  └── Guardrail → Cua（桌面）/ Playwright（浏览器）/ Shell
```

关键设计：**Linger 不自己实现 agent loop**，它把 Codex / Claude Code / Pi 当 runtime 适配进来；自己做的是"宿主 + 记忆 + 主动性 + 权限 + 界面 + 本地推理"这一层。这对复刻的含义是：**核心难点不在 agent loop，而在记忆产品化、主动性策略、桌面控制和跨平台打包**。

## 4. 复刻的三条路径

先定义"复刻"的三种含义，避免鸡同鸭讲：

### 4.1 路径 A：先用上（验证值不值得）

**前提**：一台受支持的机器。

| 平台 | 支持 | 备注 |
|---|---|---|
| macOS 14+ Apple Silicon | ✅ 桌面 App | 未签名，首次启动需 `xattr -dr com.apple.quarantine`；16GB 机器可跑（BYOK 云模型，不装本地大模型） |
| Windows x64 | ✅ 安装器/便携包 | issue 里安装类问题较多 |
| Linux x64 | ✅ tar.gz | glibc 2.35+ |
| **Intel Mac（本机）** | ❌ | README 原话："There is no package for Intel Macs; use Docker Compose there"；但 Compose 只跑服务端，Agent 仍需受支持的 Computer |

**本机结论**：这台 MacBookPro14,3（Intel i7-7920HQ / 16GB / macOS 13.7.8）**两条都不满足**（架构 x86_64、系统 < 14.0），装不了 Linger 桌面版；Docker Compose 只能起服务端，没有可连接的 Computer，等于空转。

**最小动作**：借一台 Apple Silicon Mac（≥16GB，macOS 14+）或 Windows/Linux + NVIDIA 12GB 机器，装 0.1.6，先用 BYOK 云模型跑一晚，观察"次日它能不能答出你的项目上下文 + 主动提醒是否及时"。成本：0 代码，1 天安装 + 1 晚观察。

### 4.2 路径 B：复刻"体验"到现有 DSH 栈（推荐）

你已有的资产与 Linger 组件的对应关系：

| Linger 组件 | 你已有的 | 缺口 | 补齐难度 |
|---|---|---|---|
| Harness / agent loop | DSH（web 宿主 127.0.0.1:3082，launchd 托管；子 agent、skills、工具） | 无（DSH 本身就是 harness） | — |
| 调度 / 主动触发 | DSH `schedule_create/list/view/edit` + 自动化任务页（RFC5545 重复、投递到对话）[官方文档] | 无 | — |
| 记忆 | PARA 知识库（`~/我的知识库`）+ memory-evolve + 会话记录 | 缺"实体页 wiki + change log + 出处引用"的生成流水线 | 1 周 |
| 数据源 | 飞书（lark-cli 覆盖 im/mail/calendar/minutes/note/docs）、SenseVoice ASR、dysub 夜间任务 | lark-cli 目前**仅 bot 身份**：mail 缺 scope、calendar 需用户登录（`lark-cli auth login` 人工扫码一次） | 0.5 天 |
| 主动 watcher | 飞书 bot 推送通道已通 | 缺"每 10 分钟看增量 → 判重要/紧急 → 静默时段 → 每日上限"的调度器与规则文件 | 1 周 |
| 桌面接管 | bash + 浏览器自动化 + AppleScript 可行 | 缺 Cua 级"读窗口 → 点击/输入 → 用户切走就停"的仲裁 | 2–3 周 |
| 本地模型 | ollama 0.32.5：qwen2.5:3b、bge-m3、nomic-embed-text | 缺"按硬件推荐模型/自动装载"；且本机算力只够后台小任务 | 0.5 周 |
| 语音 | SenseVoice 转写脚本（本地） | 缺实时流式 + TTS | 1 周（可选） |

**本机实测数据（支撑上面的判断）**：

- 硬件：MacBookPro14,3，Intel Core i7-7920HQ（4 核），16GB RAM，Intel HD 630（1.5GB），磁盘可用 51GB，macOS 13.7.8 [实测]
- 本地模型：`ollama run qwen2.5:3b` 实测 **8.84 tok/s**（eval 50 tokens / 5.66s；prompt eval 23.2 tok/s；load 7.95s）[实测]。结论：3B 模型可做"夜间摘要/实体抽取"这种后台批处理，做不了实时桌面 Agent 的主模型；7B 以上会更慢（[估算]，未测）。
- Docker：已装 docker + docker-compose + colima；colima 当前 **Stopped**，配置 2 CPU / 4GiB（Linger Compose 要求虚拟机内存 ≥5GiB）[实测]
- 飞书：`lark-cli whoami` → 仅 bot 身份；`calendar +agenda` 返回 authorization 错；`mail … list` 报缺 `mail:user_mailbox.message:readonly` scope [实测] → 需要一次人工 `lark-cli auth login`
- DSH：本会话为工单 worker（无 schedule 工具），但宿主 web profile 的 standard/cordis/ptc preset 带四个 schedule 工具与自动化任务页 [官方文档]

**P1–P4 里程碑（建议按这个顺序做，每步可验收）**：

| 步骤 | 内容 | 预估 | 验收标准 |
|---|---|---|---|
| P0（0.5 天） | `lark-cli auth login` 拿用户身份；确认能读飞书邮件/日历/会议纪要；选定 wiki 目录（建议 `~/我的知识库/02-Areas/个人Wiki/` 或独立 `~/.dsh/wiki/`） | 0.5 天 | 能列出"最近 7 天邮件/日程/会议纪要"的元数据（不落隐私正文） |
| P1（1 周） | **夜间 Wiki 流水线**：每晚 00:00 跑 DSH 定时任务 → 拉取当日飞书邮件/日程/会议 transcript（SenseVoice 转写）+ 当天对话 → 模型按"客户/联系人/项目/主题/会议"页做**分节 diff**（摘要重写需给理由；列表逐条改；每事实带出处）→ 写入 wiki；生成 Change Log；建全文检索（可用 bge-m3 或直接 FTS） | 1 周 | 次日问"上周 X 客户提了什么、什么时候要报价"能答对且带出处；连续 3 晚无重复页/无丢失条目 |
| P2（1 周） | **主动 watcher + 规则学习**：每 10 分钟拉增量 → 规则文件（general + learned）判"tell now / follow up later / stay silent" → 静默时段（22:00–08:00）+ 每日上限 → 飞书私聊推送；每晚从用户回复里蒸馏规则（同一类线索两次 → 规则） | 1 周 | 一周内 ≥3 次"及时且有用"提醒、误报 ≤1 次/天；静默时段生效；两次"太晚/别推"后同类自动改规则 |
| P3（2–3 周，可选） | **桌面接管**：浏览器用现有 Playwright 工具；桌面用 AppleScript/Accessibility 做"读窗口文本 → 定位控件 → 点击/输入"；写操作一律审批卡；用户一动鼠标/切窗口就停 | 2–3 周 | 完成一次"打开飞书文档改一段并保存"的端到端，全程可中断、可回放 |
| P4（0.5 周，可选） | **本地小模型后台化**：夜间 wiki 的摘要/实体抽取走 ollama qwen2.5:3b（实测 8.8 tok/s 可接受）；主对话仍走云模型 | 0.5 周 | 夜间任务不占云 token；单晚处理 30 封邮件 + 2 小时转写在 30 分钟内完成 |

**总工作量 [估算]**：P0+P1+P2 ≈ 2–2.5 周（这是"80% 体验"）；加 P3+P4 ≈ 4–6 周。依据：现有 DSH 已提供 harness/调度/记忆底座，缺口是三块明确的流水线；对照 Linger 用 18 位提交者、11 天做出 0.1.6，其中大量工作量在跨平台 GUI 与打包，自用版可省掉。

**这条路线的本质**：复刻的是 Linger 的**信息架构与交互范式**，不是它的代码。收益是可解释、可改、数据全在本地；代价是没有它的打磨（GUI、会议实时转录、模型自动驾驶）。

### 4.3 路径 C：复刻"产品"

**不建议从零**，理由（可量化）：

- Linger 已有约 **110 万行代码 / 8 个主要模块 / 1,652 个测试文件 / 686 commits / 18 位贡献者 / 11 天**；按"18 位提交者 × 11 天"粗算，已投入 ≈ **6 人月**（[估算]，未验证真实工时，仅按提交者数×天数量级）。
- 难点不在 agent loop（可直接用 Codex/Claude/DSH/Pi），而在：跨平台桌面壳与签名、Cua 级桌面控制与输入仲裁、Wiki diff 的一致性校验、主动性规则的可回滚、语音实时链路、本地推理的硬件矩阵适配。
- **许可证**：修改版 Apache 2.0 允许商用与自建，但 ① 对外提供托管/管理服务需授权；② 前端不得移除/修改 LOGO 与版权信息（`apps/web/` 或 web 服务镜像）。这意味着"fork 后换皮做 SaaS"不可行，"fork 后做内部工具/自用"可行。

**如果确实要做产品**，最小路径是：
1. fork Linger（保留 LOGO/版权，或与其商务谈授权），把连接器替换成飞书/企业微信（当前连接器只有 Gmail/Outlook/Slack/Notion/GitHub/Calendar/Drive，**没有飞书**，这是你场景的硬缺口）；
2. 或者组合：DSH（harness + 调度 + 记忆）+ 自研桌面壳 + PolyStrata/Strata（本地推理，MIT）——工作量 ≥6 人月到"可用"，且要自己解决 Cua 级桌面控制。

## 5. 本机实测结论（为什么本机不能直接复刻 Linger）

| 项 | 实测值 | 对复刻的含义 |
|---|---|---|
| 机器 | MacBookPro14,3 / Intel i7-7920HQ 4 核 / 16GB / Intel HD 630 1.5GB | 无 NVIDIA、无统一内存；**跑不了 PolyStrata/Strata**（Windows/Linux + 12GB NVIDIA 起） |
| 系统 | macOS 13.7.8（x86_64） | Linger 桌面版要求 macOS 14+ 且 Apple Silicon → **不满足** |
| 磁盘 | 可用 51GB | 125B 的 2-bit 权重约 39GB（README），加上 Docker 镜像/模型缓存会非常紧；只够小模型 |
| 本地模型 | qwen2.5:3b 实测 8.84 tok/s | 只够后台摘要/抽取；做不了"实时个人 Agent 主脑" |
| Docker/Colima | colima 停止；2 CPU / 4GiB | Linger Compose 要 ≥5GiB；抬到 8GiB 会和 DSH/浏览器抢内存（16GB 总量） |
| 飞书授权 | 仅 bot 身份；mail 缺 scope、calendar 需用户登录 | 需要一次人工扫码授权，之后 P1/P2 才能读数据 |
| DSH | web 宿主 + 调度 + 子 agent + 飞书通道 + PARA 记忆 | 复刻 B 的底座已就位 |

**因此**：在这台机器上，"复刻 Linger 本体"不可行（平台不支持 + 算力不够）；"复刻 Linger 体验"可行，且不需要 125B 本地模型——用云模型 + 3B 后台模型即可。

## 6. 推荐的最小路径（如果只做一件事）

**先做 P1（夜间个人 Wiki），一周内验收。** 理由：

1. 它是 Linger 三个差异化里**最能立刻感知价值**的一个（"它记得我的项目"），也是你现有 PARA 知识库最自然的延伸；
2. 它不依赖桌面控制、不依赖本地大模型、不依赖 NVIDIA，风险最低；
3. 做完 P1 再决定 P2/P3 是否值得投入——如果夜间 Wiki 你用不上，主动性提醒的价值也会打折。

**P1 的第一天具体动作**（可直接开工）：
1. `lark-cli auth login`（人工扫码一次），验证 mail/calendar/minutes 读权限；
2. 用 DSH 定时任务建每晚 00:00 的 job，输入 = 当日飞书邮件元数据 + 日程 + 会议纪要（SenseVoice 转写）+ 当日对话摘要；
3. 输出目录结构：`个人Wiki/{clients,contacts,projects,topics,sessions}/*.md`，每页 frontmatter 带 `sources: []`，正文分节；模型只允许"分节 diff"，每处改写写理由，Change Log 由脚本写（不让模型写）；
4. 验收：次日问 3 个跨天问题（谁、要什么、何时到期），答案必须带出处链接；答不出就标"未记录"，不许编。

**不建议的顺序**：先买 12GB NVIDIA 机器（为了 125B）→ 你会在"本地模型质量 vs 云端"上纠结很久，而 Linger 真正的护城河是记忆与主动性，不是那 45.5 tok/s。

## 7. 风险与坑（复刻前必须知道）

1. **Linger 很早期**：0.1.6、发布 11 天、18 个 open issue（安装类占相当比例）；macOS 包未签名（需手动去 quarantine）。把它当"参考实现"，别当稳定基础设施。
2. **性能数字口径**：45.5 tok/s 等多来自"大卡限制到小预算"的模拟测量；12GB+32GB 机器首 token 可能约 3 分钟。真实 12GB 3060 + 64GB 内存的表现需自测。
3. **Mac 16GB ≠ 125B**：官方 16GB 档推荐 4B 模型，且是在 24GB M6 mini 上测的；"everyday Macs"是营销话术。
4. **Intel Mac 完全不支持**（桌面版与本地模型安装器都不支持；Compose 只解决服务端）。
5. **没有飞书连接器**：Gmail/Outlook/Slack/Notion/GitHub/Calendar/Drive，六类；中文办公场景（飞书/企微/钉钉）需要自己写。
6. **许可证不是 OSI 标准**：托管服务需授权、前端不得去 LOGO → 影响产品化路径。
7. **桌面接管无沙箱**：官方文档明说"用确认卡与服务端校验限制 Agent 动作，没有采用沙箱隔离"；Agent 以你的身份操作，风险自担。
8. **本地模型与前台共享**：model scheduling 是"一个模型服务所有 agent/审批/后台任务"，本地小模型会被后台 wiki 任务拖慢（官方有优先级队列，但总量仍受限）。
9. **磁盘/内存**：125B 2-bit 权重 39GB；本机 51GB 可用 + 16GB 内存，跑不动也不该硬跑。
10. **自报基准**：LoCoMo 95% 无第三方复核；仓库有 benchmark 脚本可复跑（`apps/node-services/scripts/memory-benchmark/`），但需要模型与时间。

---

## 8. 结论

1. **文章的思路是真的**：Linger 把"个人 Agent"从聊天框推进到"宿主 + 实体化 Wiki 记忆 + 可解释主动性 + 本地推理"，这套组合值得复刻。
2. **但"复刻"要分层**：装 Linger（本机不行）→ 复刻体验（可行，2–6 周）→ 复刻产品（≥6 人月，不建议从零）。
3. **最小路径**：不追求 125B 本地化，先在 DSH + 飞书上做"夜间个人 Wiki（P1）"，一周验收，再决定主动性（P2）与桌面接管（P3）。
4. **如果要做产品**：fork Linger 或组合 DSH + PolyStrata，但先解决飞书连接器与许可证两件事。
