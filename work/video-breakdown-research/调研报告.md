# 视频拆解开源项目调研（本机可落地版）

- 调研日期：2026-11-14
- 本机条件：macOS 13.7.8 / Intel i7-7920HQ（4 核 8 线程）/ 16GB 内存 / 无 NVIDIA GPU、无 CUDA；ffmpeg N-124654；Python 3.10.9；SenseVoice-small 已缓存可离线；本机另有 Ollama qwen2.5:3b。
- 目标：给“把一条参考视频拆成分镜、口播稿、结构”的工作选一条**今天就能跑**的路线，而不是罗列论文模型。

## 0. 结论

### 0.1 今天就能用：PySceneDetect + SenseVoice + 画面换版扫描

| 层 | 用什么 | 本机实测 |
|---|---|---|
| 镜头硬切 | **PySceneDetect 0.7.3**（BSD-3，纯 Python + OpenCV/ffmpeg，CPU） | 合成 4 切点视频 4/4 全中；27s/37s 动效视频硬切为 0（渐变转场，属正常） |
| 口播转写 | **SenseVoice-small + fsmn-vad**（MIT，本地 CPU） | 37s 音频分 3 段；模型加载约 7–35s，纯推理 2.5–5s |
| 画面段落 | **1fps 采样 + HSV 直方图/像素差**（本仓库脚本自带） | 27s 动效：1/8/18/25s 四处换版；37s 动效：7/12/18/25/30s 五处；与人工看帧一致 |
| 结构分析 | 把“时间线 + 口播稿”交给文本 LLM | 建议用你常用的在线 LLM；本机 3B 模型未接入默认流程（4 核 CPU 上生成慢，质量未验证） |

仓库内附两个可直接跑的脚本：`video_breakdown.py`（硬切 + 画面段落 + 关键帧 + 口播 + Markdown 报告）和 `asr_segments.py`（SenseVoice 句级分段）。本机已用两条动效视频（27s 横屏、37s 竖屏）和一条 30s 真人口播跑通画面/镜头层；其中 37s 素材跑通含 SenseVoice 的完整链路；另用一条 9 分钟口播验证了硬切检测（76.2s）。

### 0.2 现成工具里最值得试的三个

1. **vdeconstruct（AIGC-VideoDeconstruct）**：概念最贴“视频逆向拆解工作台”——镜头、关键帧、运镜、色板、分镜板、模板渲染、AIGC 适配器、Web 编辑器，核心纯 CPU、Apache-2.0。但它是 **Alpha**（PyPI 仅 2 次发布、月下载约 65、元数据里没有公开仓库地址），本次实测 37s 视频 1 个镜头、耗时 38.7s（仅测 `analyze`/`render`，未测 ASR/人物/音频增强）；它声明 Python≥3.11，本机是强制忽略版本约束装到 3.10 才跑通的，正式用建议 3.11+。建议小样验证后再决定是否依赖。
2. **BiliSum**：B 站/YouTube/本地视频的 AI 摘要 + 图文笔记 + 思维导图 + 本地知识库；支持本地 Whisper/FunASR、本地 LLM。适合“内容总结/知识库”，不是镜头级分镜。
3. **FunClip**：基于 FunASR 的中文视频按台词切片（Paraformer/SenseVoice），本地 Gradio，适合“按口播句子剪片段”；不是结构拆解。

### 0.3 本机不要硬上

- **OmniShotCut**：官方 README 明确要求 PyTorch + CUDA；本机无 NVIDIA GPU。它提供 HuggingFace Space 在线 demo，真要用走在线。
- **AutoShot / 训练型镜头边界模型**：研究代码 + 训练依赖，未在本机验证，不建议作为生产入口。
- **Qwen2.5-VL / VideoLLaMA / InternVL 等视频理解大模型**：按公开部署要求通常要 8–24GB 显存；16GB 内存 + 无 CUDA 的机器本地跑不划算（未本机实测）。口播类拆解用“转写 + 文本 LLM”即可覆盖大部分结构信息。

## 1. 先定义“拆解”拆的是哪几层

| 层 | 产出 | 本机可行方案 | 容易踩的坑 |
|---|---|---|---|
| 镜头/分镜层 | 切点、镜头时长、转场、关键帧、景别/运镜 | PySceneDetect、ffmpeg scene、TransNetV2（可选） | 只擅长硬切；动效/口播的渐变转场会得到 0 切点 |
| 画面信息层 | 换版点、字幕/贴纸文字、色彩、主体 | 1fps 换版扫描、关键帧、OCR（可选） | 真人口播画面持续变化，绝对阈值容易每 2s 误触发 |
| 语音/文案层 | 口播稿、句级时间戳、停顿 | SenseVoice + VAD、faster-whisper、FunASR | SenseVoice 不输出词级时间戳；专有名词有错字 |
| 结构/叙事层 | 钩子、问题、论证、例证、CTA | 文本 LLM 读“口播稿 + 时间线” | LLM 会脑补，必须要求引用时间戳并人工核对 |

**关键判断**：这条视频是“影视/混剪/广告”（硬切多），还是“口播/口播+贴纸/动效模板”（几乎没有硬切）？两者的拆解主信号不同。后者用镜头数衡量会得出“只有 1 个镜头”的无用结论。

## 3. 本机实测

### 3.1 环境

- CPU：Intel i7-7920HQ，4 核 8 线程；内存 16GB；无 NVIDIA GPU。
- 系统：macOS 13.7.8；ffmpeg N-124654。
- Python：3.10.9（miniconda）/ 3.13.7（系统）；PySceneDetect 0.7.3 装在 venv（复用 conda 的 OpenCV 4.11 / numpy 2.2.6）。
- ASR：funasr 1.4.23 + torch 2.2.2（CPU，6 线程），模型 `iic/SenseVoiceSmall` + `fsmn-vad` 已缓存。
- 测试素材：本机已有的横/竖屏口播与动效视频（不公开内容）；另用 ffmpeg 合成 12s 四段纯色视频（3/6/9s 三处硬切）做正确性校验。

### 3.2 结果

| 测试 | 方法 | 结果 | 耗时 |
|---|---|---|---|
| 合成 4 段 12s（640×360，3/6/9s 硬切） | PySceneDetect ContentDetector | **4/4 全中**，边界 3.0/6.0/9.0s | 0.37s |
| 合成 4 段 | PySceneDetect AdaptiveDetector | 4/4 全中 | 0.31s |
| 27s 1920×1080@60 动效模板 | PySceneDetect ContentDetector | 0 个硬切（整段 1 个镜头） | 约 5–10s |
| 27s 同一素材 | ffmpeg `select='gt(scene,0.3)'` | 0 个硬切 | 9.13s |
| 27s 同一素材 | 1fps 换版扫描 | 4 个换版点：1/8/18/25s → 5 段；与人工看 1fps 缩略图一致 | 约 1s |
| 37s 1080×1920@30 动效 | PySceneDetect | 0 个硬切 | 5.1s |
| 37s 同一素材 | 1fps 换版扫描 | 5 个换版点：7/12/18/25/30s → 6 段 | 1.0s |
| 37s 同一素材 | vdeconstruct `analyze`（basic，另测 `render`） | 1 个镜头、1 张代表帧、色板/运动有输出；`render` 可出模板化拉片 Markdown；未测 ASR/人物/音频增强 | 38.7s |
| 30s 1080×1920 真人口播 | PySceneDetect | 0 个硬切 | 约 2–5s |
| 30s 真人口播 | 1fps 换版扫描 | 逐秒变化持续偏高（中位分 0.595），自动跳过，避免产出 15 个假段落 | 约 1s |
| 541.8s 576×1024 HEVC 口播 | PySceneDetect ContentDetector | 0 个硬切 | 76.2s |
| 37s 音频 | SenseVoice（模型已热） | 全文一次输出 | 3.2s |
| 37s 音频 | SenseVoice + fsmn-vad 分段 | 3 段：0.0–11.4 / 11.9–24.5 / 25.0–34.3s；纯推理 2.5–5.1s | 模型加载 7–35s + 推理 2.5–5s |

**ASR 质量**：整体可读、带标点；但专有名词/同音字会错（测试样本里出现把“上手试”识别成“上首势”、“决定”识别成“决饼”这类错误）。报告里引用原句前必须校对；用于结构分析（找钩子/段落）影响不大。

**完整流程**：37s 素材跑 `video_breakdown.py` 两次总耗时 36.5–58.0s；硬切 5–11s、画面扫描 1.0s、关键帧 6 张、口播 26.7–40.4s（模型加载 24–35s、推理 2.5–5.1s）。模型热起来后口播可到 3s 量级；批量处理建议常驻进程。

### 3.3 未实测（不要当成已验证）

TransNetV2、OmniShotCut、AutoShot、FunClip、BiliSum、auto-editor、NarratoAI、media-engine、ffcine、两个 Agent Skill 均**没有**在本机跑通或评估精度；表中结论来自仓库 README/PyPI 元数据与代码定位，属于“选型判断”，不是实测。视觉大模型（Qwen2.5-VL 等）也未在本机跑。

## 4. 关键发现

1. **“0 个镜头”不是拆解失败**。两条本地动效视频（27s、37s）和一条 9 分钟口播都是 0 硬切：动效模板用渐隐/叠化，口播是单镜头。用镜头数评价这类视频会得出错误结论。
2. **1fps 换版扫描能补上“没有硬切”的结构信息**。27s 的 1/8/18/25s、37s 的 7/12/18/25/30s 与人工看帧的版块切换一致；耗时约 1s。
3. **绝对阈值不能直接套到真人口播**。30s 真人口播的逐秒画面差全部偏高（中位分 0.595），按 0.16 阈值会每 2s 出一个假段落；脚本现在用“硬切为 0 且中位分 >0.35 → 自动跳过”的守卫，避免噪声。
4. **ffmpeg scene 与 PySceneDetect 在硬切上一致，都怕渐变**。合成视频两者都 4/4；动效视频两者都 0。不要把“0 切点”归因于某一个工具坏了。
5. **本机最稳的分工**：镜头层交给 PySceneDetect（便宜、快、BSD-3），语音层交给 SenseVoice（本地、中文强），结构层交给文本 LLM；不要把预算花在本地视觉大模型上。
6. **vdeconstruct 是“最像成品”的现成工作台，但成熟度不够**：PyPI 仅 1.9.1/1.9.2 两次发布（同日）、Alpha、月下载 65、无公开仓库链接；本次 37s 视频 38.7s、1 个镜头。功能清单很吸引人（分镜板/SVG/模板/色板/运镜/适配 Wan/可灵/Runway/Pika），适合先拿一个项目试，不适合直接当生产依赖。

## 5. 推荐路线

### A. 今天就能用（已本机验证，零重型依赖）

```bash
cd work/video-breakdown-research
# 一次性环境（本机已验证：复用 conda 的 cv2/numpy，避免重装 OpenCV）
python3 -m venv --system-site-packages .venv-scene
.venv-scene/bin/pip install scenedetect

# 拆一条视频
.venv-scene/bin/python video_breakdown.py "/path/to/video.mp4" -o out/
```

产出：

- `out/report.md`：素材信息、硬切数、画面段落时间线、口播分段、结构拆解模板；
- `out/breakdown.json`：给后续脚本/LLM 用；
- `out/keyframes/*.jpg`：每段代表帧；
- `out/asr.json`：句级转写（如 ASR 环境可用）。

口播转写需要 funasr/torch/soundfile 环境。脚本会自动找 `~/src/compare-ocr-models-*/test/venv/bin/python`，也可用 `SENSEVOICE_PY` 指定；找不到时退回 `~/.local/sensevoice-asr/transcribe.sh`（只有全文、无时间戳）。

**结构分析提示词**（把 `report.md` 的时间线和口播稿贴进去）：

```text
你是短视频结构拆解助手。根据下面的时间线与口播稿，输出 JSON：
{"hook":{"start":0,"end":..,"role":"钩子","summary":".."},
 "sections":[{"start":..,"end":..,"role":"..","summary":".."}],
 "cta":{"start":..,"end":..,"summary":".."},
 "one_line":".."}
要求：只使用给定时间戳；每段 summary 不超过 40 字；不要脑补画面；
不确定的字段填 null。时间线：<粘贴>；口播稿：<粘贴>。
```

### B. 要专业镜头语言/影视分镜

1. 先用 PySceneDetect 出硬切与关键帧；
2. 需要更高召回（渐变/快切）时上 **TransNetV2**（CPU 可推理，但要接受 torch 依赖与速度）；或直接走 **OmniShotCut** 的 HuggingFace Space；
3. 需要“分镜板 + 运镜/色板 + AIGC 提示词”时，拿 **vdeconstruct** 小样验证：它的 `analyze` + `render --template general-film-analysis --layout storyboard` 能直接出模板化拉片报告。

### C. 要“内容总结/知识库/切片”而不是分镜

- **BiliSum**：本地视频→摘要/图文笔记/思维导图/知识库；
- **FunClip**：按台词选段切片（中文）；
- **auto-editor**：口播去静音/粗剪；
- **NarratoAI**：影视解说成片（需要 LLM API，重）。

### D. 不建议在本机投入

OmniShotCut 本地 CUDA 推理、AutoShot 训练、Qwen2.5-VL/VideoLLaMA 等 VLM 本地推理；以及任何要求“先下 7B 模型再拆 30 秒视频”的方案。

## 6. 风险与限制

- **素材获取**：本机抖音下载链路有已知限制（yt-dlp 接口失效），拆解流程默认你已经有本地视频文件；平台视频版权/条款自行确认。
- **准确性**：ASR 会错专有名词；1fps 换版是启发式（±1s），不是镜头语言级分镜；硬切检测漏渐变。
- **未做的能力**：OCR 画面文字、景别/运镜分类、说话人分离、节奏/情绪曲线。这些是下一步，不是本脚本的现有能力。
- **vdeconstruct 风险**：Alpha、无公开仓库地址、下载量小；不要把它作为唯一产出路径。先用一条 30–60s 素材验证镜头数/关键帧/导出是否符合预期。
- **许可**：PySceneDetect BSD-3、SenseVoice/FunASR/FunClip/BiliSum/TransNetV2/OmniShotCut/AutoShot/NarratoAI/clipsai MIT、auto-editor Unlicense、vdeconstruct Apache-2.0、ffcine Apache-2.0、video-reverse-engineering MIT、video-replication-breakdown-skill 无 License。商用前逐项复核模型权重与素材版权。
- **LLM**：结构拆解结果必须回到原视频抽查；LLM 容易把“推测”写成“事实”。
