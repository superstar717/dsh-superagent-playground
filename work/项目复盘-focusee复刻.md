## 二、做得对的

1. **净室研究先于写码**：AX 树字段与官网文案逐字对应，33 分钟出原型且样式字段名与原版一致。
2. **差异如实记录**：DIFF-REPORT 把「点击检测是近似（停留簇 vs 真实点击事件）」列为最重要
   行为差异，不夸大复刻程度。
3. **PR #34 起方法论升级**：真机复现矩阵（修复前必失败 / 修复后必过）+ 崩溃 .ips + 抽帧验证
   成片——不再拿单测绿当交付。
4. **每个真机反馈都沉淀为回归资产**：多段/取消/拖动 e2e 场景、6 条 tripwire 单测
   （renderer 禁引用 `mainWindow`、回调禁读全局状态、main.js 禁对悬浮/预览窗口
   executeJavaScript、闩锁必须复位）。
5. **用 git 证据纠自己的错**：PR #34 用 diffstat 指认 abe059e「声称移除、实际没移」；
   用户旧录像静帧的根因如实归档为旧构建问题并复核确认。
6. **工单拆分干净**：每类真机问题一个新工单/新 PR，证据各成档，可追溯。

## 三、犯过的错（按伤害排序）

1. **交付门错位**：PR #32 开出时 e2e 只验证导出链路，录制链路在真机的权限/窗口/资源现实
   全没验证——黑屏、时长 0、按钮无响应、停止退出全靠用户踩出来（6 次用户往返中 4 次属于
   「打包应用真机 e2e + 抽帧断言」本可拦下的缺陷）。
2. **跨进程边界随手抄**：f616f88 把 main.js 的 `mainWindow` 抄进 renderer，try/catch
   各抛一次打断整条保存链（录制必丢 + 编辑器不回前台 = 用户视角「直接退出」）。
3. **修复声明与 diff 不一致**：abe059e 声称移除崩溃调用，diffstat 只有 renderer/control.js，
   main.js 里崩溃调用原样保留——「声称修了」比「没修」更糟，用户再崩一次才被发现。
4. **复用状态不复位**：悬浮条窗口跨录制复用，stopped 闩锁首次停止后不复位，第二次停止被
   静默吞掉；单次流程验证天然测不到「第二次」。
5. **从未测试过的路径就是会崩**：e2e 从不移动窗口（reportMove 空引用）、从不用横幅相机
   （圆烘焙上下出界）——两条都是用户先看到。
6. **依赖系统行为未验证**：`setContentProtection(true)` 在 macOS 15+ ScreenCaptureKit 下
   失效（公开 issue 可查），「控制条不入镜」靠一个已不成立的假设撑到用户发现入镜。
7. **文档漂移**：DIFF-REPORT 最后更新于 23:44，此后人像分割去背景、实时画中画、
   控制条入镜事实都没回写；表内残留矛盾（3D 动效同时标 ✅近似 与 ❌、背景移除已落地仍标 ❌、
   内容保护行为已证伪仍标 ✅）。

## 四、如果重来会怎么做

1. **开工先立「真机验收门」**：打包应用 + 含摄像头 + 连续 ≥2 段 + 取消路径 + 真实拖动窗口 +
   抽帧断言成片内容，PR 合并前必须全过——本项目 6 次用户往返中 4 次可被它拦下。
2. **第一天定跨进程铁律**：主进程不向其它窗口注入 JS（只走 ipc 事件）、renderer 不引用
   主进程标识符——tripwire 当天加上，而不是崩过之后才加。
3. **功能扩充与稳定性修改分开提交**，每个提交后跑完整真机 e2e（f616f88 这类「稳定性」提交
   恰恰是致命回归源）。
4. **修复 PR 的每条行为声明先在 diff 里指出来**再写 commit message；复审用
   `git show --stat` 对账。
5. **首轮交付就把「已知差异 vs 期望范围」与用户对齐排优先级**（「复刻的不够」本可提前避免）。
