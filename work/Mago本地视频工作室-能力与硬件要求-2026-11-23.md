# Mago 本地视频工作室：能力、硬件要求与 12G 显存 PC 对照

> **调研时间**：2026-11-23 12:55–13:20 CST  
> **上游版本**：`MagoStudio/MagoStudio` @ [`57dba32`](https://github.com/MagoStudio/MagoStudio/commit/57dba32353e63cc53578273806566ace6044953e)（v0.21.0，2026-11-20）；官网/文档抓取于 2026-11-23  
> **方法**：官网、README、`docs.mago.studio`、仓库代码与 release/issue、MiniMax H3 官方模型卡与 License；本机用 SSH **只读**读取 12G 显存 PC 的硬件与磁盘（**没有安装 Mago、没有实测渲染**）。  
> **证据等级**：**A**=官网/仓库 README/官方模型卡；**B**=官方文档或仓库代码；**C**=维护者回复/第三方实测；**D**=消息里的单方说法或未验证内容。  
> **一句话结论**：Mago 是真的，12G 显存的 RTX 3060 也能跑本地 H3；但它属于安装向导的 **“limited”** 档——12G 只是 H3 的现实下限，这台 PC 真正的短板是 **16GB 内存** 和 **C 盘空间**。纯本地的 Mago 只覆盖“改写已有素材”的子集，**mask inpaint、ControlNet、16-bit EXR、2K 都在 Mago Cloud**，不在本地。

## 1. Mago 到底是什么

### 1.1 产品定位

Mago Studio 是 Mago AI 视频编辑器的**本地优先桌面版**：Electron 43 + Next.js 16 + TypeScript，项目/素材留在本机，渲染走本机 ComfyUI 或登录后的 Mago Cloud。【A】

- **本地渲染免费**，不消耗云 credits；云端模型需要 Mago 账号和付费 credits。【A】
- 两条主工作流：
  - **Mago Director**：剧本 → 选角/资产 → 镜头表 → 分镜 → 逐镜头生成，面向长片/剧集；官网称“从想法/剧本到成片”的长片模式仍是 alpha。【A】
  - **Mago Transform**：已有素材的整段改写/风格化、局部蒙版编辑、重新打光、角色替换；按镜头、按帧范围、带版本历史。【A】
- 也支持“生成”：从单帧/参考图驱动一个新镜头；官网 FAQ 明确说“Not any more（不再必须有素材）”，但完整长片生成在 alpha。【A】

> **一处官方口径冲突**：`docs.mago.studio` 的产品哲学页写 **“Mago is not a video generation product. It does not create videos from scratch or from text alone.”**（[Introduction](https://docs.mago.studio/guide/introduction)）；官网和 README 又说 Director/生成。两者并不完全一致。我的处理：把它理解为“**核心是 Transform，生成是后加的能力**”，不把“从零文生视频”当成它的强项。

### 1.2 本地和云端是两套模型，不是同一个东西

这一点最关键，也是消息里最容易混淆的地方：

| | 本地（本机 GPU + ComfyUI） | 云端（Mago Cloud） |
|---|---|---|
| 视频主模型 | **MiniMax H3（Local）**，含 4-step turbo / 8-step PDD / VFX LoRA | **Mago 自家模型族**（Mago Transform / Style Transfer / Character / Inpaint / Clean Plate 等，v2.5–v8），以及 Kling、Seedance、Happy Horse 等伙伴模型 |
| 控制能力 | H3 的 VFX 模式；无 ControlNet 选项；无 mask inpaint | ControlNet（depth/pose/softedge/normal）、mask inpaint、16-bit EXR、HDR、2K、4K（部分伙伴模型） |
| 时长/分辨率 | 单镜头 1–15s；480p/720p/1080p（1080p 实验性） | 依模型，4–30s；720p/1080p/4K；2K 需 H3-Regenerate-2K（未开源，托管端） |
| 费用 | 免费（自己的电/硬件） | 账号 + credits（付费） |

【A/B】来源：README、[Model Catalog](https://docs.mago.studio/models/overview)、仓库 `src/platform/localVideoModels.ts`、`src/app/models/video/minimaxH3LocalModel.ts`、`docs-public/architecture.md`。

**所以消息里“Mago 默认调用 H3，H3 是引擎、Mago 是方向盘”这个比喻方向是对的，但只对“本地”成立。** 云端 Mago Transform 用的是 Mago 自己的模型族；H3 是本地默认引擎，不是 Mago 的唯一引擎，也不是云端 Transform 的同义词。

### 1.3 本地模型不止 H3

`Minimal` 组只装 H3 + Qwen3-VL 4B 字幕模型；其余是可选的【A/B】：

- **Mago Style Transfer (Local)**：Wan2.2 Fun Control 管线（FP8 或 GGUF Q8/Q6/Q5/Q4），5–81 帧，512–1920 输出；需要另外下 Wan 系模型（不在 Minimal 里）。
- **Mago Animate (Local)** / **Wan2.2 Animate** / **Wan VACE 2.1**：需要手动装节点包和模型。
- **LTX 2.3 Spatial Upscaler**：本地超分，需手动模型。
- 可选 **Local LLM**（Qwen3.8 27B，Q3 13.15GB / Q5 20.88GB，24GB+ 显存才默认 Q5）、**Qwen Image 2512**、**Flux 2 Klein 4B**。

对 12G/16GB 内存的机器，实际主路径就是 **H3（改写）+ 可选 Wan Style Transfer（风格化）**；本地 LLM 和图像组不是必装，装了也会挤内存。

## 2. 本地能力边界：哪些是“真本地”，哪些只在云端

| 能力 | 本地（H3 / 12G 路径） | 云端（Mago Cloud） | 依据 |
|---|---|---|---|
| 整段改写 / restyle | ✅ H3 Multipurpose / VFX edit；参考图最多 9 张 | ✅ Mago Transform；ControlNet 可调 | 【B】本地模型定义；【B】文档 |
| 风格迁移 | ✅ H3 style-transfer LoRA，另有 Mago Style Transfer (Local)（Wan2.2） | ✅ Mago Style Transfer | 【B】 |
| 换头 / 换人 | ✅ H3 head swap / character swap LoRA | ✅ Mago Character | 【B】 |
| 新机位（camera angle） | ✅ v0.21.0 新增，H3 crossview LoRA + depth + CrossViewWarp，需单独模型组 | 未见同名云端项 | 【A】v0.21.0 release notes |
| **mask inpaint / 局部蒙版** | ❌ 本地 H3 模型定义里没有 mask 输入（`grep -i mask` 0 命中）；Mask 工作区只能导出 mask 给外部合成 | ✅ Mago Inpaint（mask 输入） | 【B】代码；【B】文档 |
| **ControlNet（depth/pose/softedge/normal）** | ❌ 本地 H3 没有 ControlNet 设置 | ✅ Mago Transform 的 ControlNet | 【B】代码；【B】文档 |
| **16-bit EXR / HDR** | ❌ 本地 H3 `save_exr: false`；本地模型没有 EXR 导出设置 | ✅ Mago Transform / Style Transfer 可导 EXR 16-bit；SDR-to-HDR 输出 EXR | 【B】代码；【B】[Export & compositing](https://docs.mago.studio/guide/export-and-compositing) |
| **2K/4K 输出** | ❌ H3-Base 本地只出 768p 短边；H3-Regenerate-2K 未开源 | ✅ 云端可到 2K/4K（依模型：Mago Style Transfer 最长边最高 3840，Kling 等伙伴模型 4K；H3 2K 在托管端） | 【A】MiniMax H3 模型卡；【B】Mago 文档 |
| 超分 | ✅ LTX 2.3 spatial upscaler（手动模型） | ✅ Mago Upscaler / Creative Upscaler | 【B】 |
| 长片/剧集管理 | ✅ 项目→镜头→轨道→版本 | ✅ 同 | 【B】 |
| 剧本→镜头 | 可接本地 Qwen3.8 27B + Qwen Image/Flux，但模型要另装、内存吃紧 | ✅ 完整 Director | 【B】 |

**一句话**：消息里说的“restyle、inpaint、ControlNet、16-bit EXR”是 **Mago Cloud 模型族（Transform / Inpaint / Style Transfer）的能力**，不是 12G 本地 H3 的能力。纯本地只剩 restyle / 风格迁移 / 换头换人 / 新机位。**如果“本地”是硬要求，inpaint 和 ControlNet 必须放弃；否则就要接受云端付费。**

## 3. 官方硬件要求（逐项）

### 3.1 GPU / 显存

- **官方唯一支持的是 NVIDIA**；官方最低 **8GB VRAM**，**约 63GB** 空闲磁盘。【A】[下载页](https://www.mago.studio/download)、[README](https://github.com/MagoStudio/MagoStudio/blob/57dba32353e63cc53578273806566ace6044953e/README.md#L102)
- 安装向导内部判定（v0.21.0 代码）：
  - `< 8000 MiB` → **blocked**
  - `8000–15999 MiB` → **limited**（UI 文案：“Mago will run, with limits. Smaller models run here. Larger ones stay on Mago cloud.”）
  - `≥ 16000 MiB` → **ready**
  - 依据：`desktop/main/localSetup/resolveHardwareVerdict.ts` L6–7、L29–31；`LocalSetupWizard/LocalSetupHardwareStep.tsx` L138+。【B】
- 8GB 卡的实际体验（维护者回复）：**“480p 5s renders tops. It might still need about 32gb RAM.”**（issue #6）【C】；8GB 是“能启动”，不是“能用”。
- AMD：官方不承诺。维护者回复“可以用 I have ComfyUI 选项，自己装模型和节点试试”（issue #3）【C】。
- Apple Silicon：**当前不支持**。维护者回复 M 系芯片的硬件检查不通过，“还要约 32GB 统一内存”（issue #19，仍 open）【C】。所以“macOS 版”能装/能用云，但**本地渲染在 Mac 上基本不可用**。

### 3.2 磁盘

- **63GB** 是“模型 + ComfyUI 引擎 ZIP + 解压”的总预留；**Minimal 模型本身约 54GB**。【A】README；【B】[manual-setup.md](https://github.com/MagoStudio/MagoStudio/blob/57dba32353e63cc53578273806566ace6044953e/docs-public/manual-setup.md#L152)
- 自己已有 ComfyUI：官方说 **约 54GB 模型** + ComfyUI ≥ 0.34.0 + 三个节点包。【A】README
- v0.21.0 把 crossview LoRA 从 starter 移到可选组，**starter 下载缩小约 1.26GB**；但官方页面仍写 63GB，按 63GB 预留最稳。【A】v0.21.0 release notes
- 模型清单（十进制 GB，Minimal）【B】：
  - H3 扩散模型 `minimax_h3_ref2va_pruned_int8_convrot` **20.97GB**
  - 文本编码器 `qwen3vl_32b_minimax_h3_nvfp4_awq` **15.69GB**
  - 视频 VAE 5.21GB + 音频 VAE 0.61GB
  - 4-step turbo LoRA 1.96GB + 8-step PDD-Acc 1.37GB + VFX/换头/换人/风格 LoRA 合计约 3.6GB
  - Qwen3-VL 4B 字幕模型 4.84GB

### 3.3 内存（官方没有写，但这是 12G 档的命门）

- Mago **公开页面没有给 RAM 门槛**；安装向导只“读取并报告”RAM，不做判定（`docs-public/manual-setup.md` L114；`architecture.md` 只写 GPU 分档）。【B】
- MiniMax H3 的独立社区指南给的是：**12GB 卡 + 32GB 内存**是 ComfyUI 标准路径的现实门槛；0.4MP/5s、15 步约 6 分钟；1344×768 R2V + Turbo 约 10 分钟；**只有 16GB 内存会拖到 20–29 分钟**（因为每一步都要从 NVMe 重新读 21GB 权重）。【C】[MiniMax H3 显存指南](https://minimaxh3.app/zh/posts/minimax-h3-vram-requirements)（第三方站点，非 MiniMax 官方）
- 这不是 Mago 独有的问题，是 H3 33B 权重 + ComfyUI offload 的物理限制。

### 3.4 系统 / ComfyUI / 源码

- **Windows**：一键安装，向导装 ComfyUI、节点包、模型，并校验每个文件；可暂停/续传。【A】
- **macOS / Linux**：不搞一键安装，连自己的 ComfyUI（默认 `http://127.0.0.1:8188`）；需要 **ComfyUI v0.34.0+**、**KJNodes**、**VideoHelperSuite**、**MiniMax-H3-PDD-Acc** 三个节点包、约 54GB 模型。【A】README
- **从源码跑**：Node.js 24.15 + npm 11；本地渲染要求同下载版。【A】
- 已有 ComfyUI 的坑：README 明确建议用向导装的 portable 版，自己接可能因节点/Python 版本不匹配出问题。【A】

## 4. 对照这台 12G 显存 PC（本机实测硬件）

### 4.1 实测配置

| 项 | 实测值 | 说明 |
|---|---|---|
| GPU | **NVIDIA GeForce RTX 3060，12288 MiB** | 12GB 档；驱动 621.24；compute capability 8.6（Ampere） |
| CPU | Intel Core i5-12490F | 6P 核，够用；不是瓶颈 |
| 内存 | **16GB（2×8GB DDR4-2133，两条插槽已满）** | 主板 ASUS PRIME H610M-A D4，DDR4、2 DIMM；升级要换两条，不能加一条 |
| 系统 | Windows 10 专业版 22H2（10.0.19045） | 官方未列最低 Windows 版本；Win10 22H2 未见阻断 |
| 磁盘 | C: 100GB 分区（NVMe，剩 **47GB**）；D: 365GB 同盘（剩 **279GB**）；E: 2TB HDD（剩 1.9TB）；F: 约 238GiB SATA SSD（剩 233GiB） | C 盘不够 63GB；**D 盘是同一块 NVMe，最合适**；E 是机械盘，模型加载会慢 |
| 主板 | ASUS PRIME H610M-A D4 | DDR4、2 槽，支持 32GB/64GB 套条 |

【本机】2026-11-23 通过 SSH `nvidia-smi`、`wmic`、`Get-Partition` 读取；只读，未安装软件。

### 4.2 判定

**能跑，但属于“limited”档，且瓶颈不在显存。**

- **GPU 过关**：12GB 正好是社区 H3 的“现实门槛”；官方把 8–16GB 判为 limited，12GB 在其中。
- **内存是短板**：16GB 远低于 12GB 卡跑 H3 建议的 32GB；H3 基础权重约 42GB，offload 会把内存/磁盘当二级显存。社区数据：同样 12GB 卡，16GB 内存比 32GB 内存慢 2–4 倍。
- **磁盘要选对**：C 盘 47GB < 63GB，默认装 C 会在“检查空间”这步失败；装 **D:\MagoStudio**（NVMe、279GB 空闲）即可。E 盘虽大但是 HDD，H3 offload 会非常慢，不建议。
- **系统可用**：Win10 22H2 未见阻断；最新 v0.21.0 目前只发 Windows 包，v0.20.2 也有 Windows 包。Mac 本地渲染在这台机器之外，不作为选项。

### 4.3 预期速度（务必按“草稿机”预期）

- Mago 本地 H3 默认 **720p + High（PDD 8 步）**；可切 **Medium（4-step turbo）** 和 **480p**。【B】`minimaxH3LocalModel.ts` L380–400
- 社区 12GB 数据（0.4MP≈768×512，5s）：
  - 32GB 内存、15 步：约 **6 分钟**；1344×768 R2V + Turbo：约 **10 分钟**
  - 16GB 内存：**20–29 分钟**
- 本机 720p 约 0.92MP，是 0.4MP 的约 2.3 倍像素；耗时不会线性，但**单条 5 秒大概率 15 分钟起，16GB 内存下可能 30 分钟以上**。【估算，非实测】
- 建议第一次就跑 **480p / 5s / Medium**，确认能出片、看显存/内存峰值，再逐步上 720p。**不要一上来跑 1080p 或 15 秒。**

### 4.4 升级优先级

1. **内存 16GB → 32GB（最高性价比）**：换 2×16GB DDR4-3200（H610M-A D4 两条槽；当前 2133MHz 偏低）。32GB 是社区 12GB 卡跑 H3 的最低建议；64GB 更稳。
2. **磁盘位置**：装 D 盘；不要把模型放 E 盘 HDD。
3. **GPU**：12GB 先够草稿；要批量/更高分辨率再上 16GB+（4070 Ti Super / 4080 / 5070 Ti 级）。但注意：**即使 24GB，本地 H3 的原生输出仍是 768p 短边（Mago 的 1080p 是实验档），2K 仍在云端**。
4. **不要为“本地 2K”升级**：H3-Regenerate-2K 未开源，本地任何卡都出不了 2K。

## 6. 技术真相：H3 是什么，本地那套图在做什么

### 6.1 H3 的官方事实

- H3 是 MiniMax 的**通用全模态生成模型**，不是 Mago 自研：33B 参数**稠密单流 Transformer**（H3-Omni-Transformer），约 13B 在 AdaLN 分支（推理可预计算/缓存，不必加载）。【A】[MiniMax H3 模型卡](https://modelscope.cn/models/MiniMax/MiniMax-H3)
- 输出：**4–15 秒、24 FPS、短边默认 768px、32kHz 立体声**；2K 由 **H3-Regenerate-2K** 二次生成，该模块**未开源**，只在托管 API/云端可用。【A】
- 输入：H3-Base-FL2VA（0/1/2 张图，文生/首帧/尾帧/首尾帧）；H3-Base-Ref2VA（≤9 图、≤3 视频、≤3 音频，混合最多 12 个文件）。【A】
- 本地权重（Mago Minimal）：pruned int8 扩散模型 20.97GB + nvfp4 文本编码器 15.69GB + 两个 VAE + LoRA + Qwen3-VL 4B，合计约 54GB。【B】

### 6.2 本地 H3 的 ComfyUI 图（源码级）

`desktop/main/imageRenders/comfyMiniMaxH3Client.ts` 里，Mago 为每个镜头生成的图大致是：

1. `UNETLoader` 加载 int8 扩散模型；
2. `MiniMaxChunkFeedForward`（`chunks: 4`, `seq_threshold: 4096`）做 FFN 分块，**降低峰值显存**；
3. `CLIPLoader` 加载 Qwen3-VL 32B（type `minimax`），不是 CLIP；
4. `MiniMaxH3ReferenceToVideo` 接收参考图/参考视频 + prompt + 音频 VAE；
5. `MiniMaxH3SigmaShift`、`BasicGuider`、`SamplerCustomAdvanced`（euler）采样；
6. `VAEDecode` + `VAEDecodeAudio` 解出画面和 32kHz 音频；
7. `CreateVideo` 把画面+音频合成 24fps 视频，`SaveVideo` 落盘。

【B】`comfyMiniMaxH3Client.ts` L249–331。

**这张图里没有的东西**：没有“多层 helical 缓存”，没有“不同分辨率/帧率片段并行进出显存”，没有 ControlNet 预处理链，没有 mask 输入。所谓“分块”只是 `MiniMaxChunkFeedForward` 的 FFN 分块和 ComfyUI 的 offload，目的是**把 42GB 基础权重塞进 12GB 卡**，不是并行多分辨率缓存。

### 6.3 “Transform”是产品功能，不是 H3 的架构

- 本地 H3 的 VFX 模式：Multipurpose、VFX edit、Head swap、Character swap、Style transfer、New camera angle（v0.21）。【B】
- 云端 Mago 模型族（Transform / Inpaint / Style Transfer）提供 ControlNet、mask inpaint、EXR 等；官方没有说它们“基于 H3”。【B】
- 所以“H3 transform 流水线”这个叫法本身就把 **模型（H3）** 和 **产品功能（Transform）** 揉在了一起；视频里的“Hierarchical Helix”在官方资料和源码里查不到，属于未经验证的转述。

## 7. 建议：这台 12G PC 怎么用 Mago

### 7.1 如果只是想试本地

1. **装到 D:\MagoStudio**（NVMe，279GB 空闲），不要用 C（47GB）或 E（HDD）。
2. 先跑 **480p / 5s / Medium（4-step）**，确认能出片；再试 720p。
3. 在模型设置里开 **low-vram**（Mago 对 portable ComfyUI 会加 `--lowvram`）；出 OOM 再逐项加 `--reserve-vram` 等，不要一次叠满。
4. 渲染时关掉其他吃显存/内存的程序；16GB 内存下不要同时开浏览器几十个标签。
5. 预期：**单镜头草稿机**，不是批量机；一条 5 秒要按十几分钟到几十分钟排期。

### 7.2 如果要做生产

1. **先加内存到 32GB**（2×16GB DDR4-3200；当前 2×8GB 2133 占满两槽，必须换套条）。这是投入最小、收益最大的一项。
2. **本地只做“改写已有素材”的草稿**：restyle、换头/换人、风格迁移、新机位。
3. **inpaint / ControlNet / 16-bit EXR / 2K / 伙伴模型 → 走 Mago Cloud**（付费）或外部工具；不要在 12G 本地死磕。
4. **要批量/高分辨率再考虑 16GB+ GPU**；但记住本地 H3 上限仍是 768p 短边，2K 不在本地。
5. **Mac 不作为本地渲染选项**；Linux + NVIDIA 可以，但要自己维护 ComfyUI。

### 7.3 如果目标是“口播视频剪辑”

Mago 的主定位不是口播剪辑器。它是“AI 镜头改写/生成工作室”，不是剪映/达芬奇的替代品。12G PC 做口播的主链仍是剪映/达芬奇 + 配音/字幕工具（见本仓库 `work/12G显存PC做口播视频-可行性与分工-2026-11-21.md`）。Mago 更适合作为“需要 AI 改画面/做风格化镜头”的补充，而不是口播主链。
