## 二、实际安装

### 桌面版（ZCode.app）
- 命令：`brew install --cask zcode`（中途宿主重启一次，清掉 `.incomplete` 缓存重跑成功）
- 结果：`/Applications/ZCode.app`，版本 3.18.2（build 3.18.2.10443）
- 完整性：
  - dmg sha256 `a3a3823c02a2c64f2fcb9402efe2eb88b7b7b97cb6627f7a7e1fe1757e0e9a07` = cask 钉值**逐位一致**（即官方 CDN 产物）
  - `codesign --verify --deep --strict` OK；TeamIdentifier `8A5X4JJ39T`，Bundle ID `dev.zcode.app`
  - ⚠️ 与 GitHub Release 附带的 SHA256SUMS（`d99bf2b4…`）**不一致**：CDN 产物与 GitHub 资产字节不同（重打包/签名时间戳差异）。已安装件的代码签名验证通过，完整性以 codesign+TeamID+CDN sha256 为准；此差异如实记录。
  - spctl（Gatekeeper）在线评估悬挂未返回（Apple notarization 服务间歇慢）；应用带 quarantine 属性，用户首次打开时 Gatekeeper 正常校验。

### CLI（终端 Agent）
- 源码：浅克隆官方仓库 `~/.local/zcode-src`（commit `fec97590` "chore: sync ZCode source v3.18.2"，364MB）
- 依赖：`npx pnpm@10.33.2 install --frozen-lockfile`（11m42s；pnpm 安全策略仅跳过 core-js 的 postinstall 广告脚本，无害）
- 构建：`npx pnpm@10.33.2 --filter @zcode/cli... build`（产物 `apps/zcode-cli/packages/cli/dist/zcode.cjs`）
- 入口：`~/.local/bin/zcode` 包装器 → `exec node <dist>/zcode.cjs "$@"`（与官方 install.sh 的 bin 约定一致；Node 用本机 nvm v24.15.0，官方要求 Node 24+）

## 五、复盘要点（工单收尾）

**最终事实**：ZCode.app 3.18.2 装入 /Applications（sha256 与 cask 钉值位位一致，codesign OK）；CLI 0.17.1 源码构建装到 ~/.local/bin/zcode，官方五项自检全过。声称 vs 验证：以上全部实测验证；未验证=真实模型调用（需用户登录）、桌面 App 首次启动（留给用户点开过 Gatekeeper）。

**做得对**：没有照抄网上文章的 npm 安装命令（全是坑），先查官方仓库/npm registry/CDN 实测再定方案；两条交付（桌面+CLI）分别选了官方二进制与官方源码构建。

**犯过的错**：
1. 第一轮把 `brew info zcode` 与 `brew info --cask zcode` 当两个通道等价查——实际 Homebrew 只有个 cask（无 formula），浪费一轮。推翻证据：`brew info zcode` 输出即 cask 内容。
2. 对 `zcode.z.ai/install.sh` 的 307 误读为"安装脚本存在"，跟踪重定向后实为 SPA 兜底 404。推翻证据：`curl -fsSL` 跟随重定向返回 404。
3. spctl 在线评估悬挂后反复等待两轮才放弃——codesign 证据已足够时应在第一轮就降级处理。推翻证据：spctl 两次 45s+ 无输出，属 Apple notarization 服务端间歇问题，与本机安装质量无关。

**如果重来**：直接按「官方 Releases/brew cask 装桌面 + quickstart 构建 CLI」两步走，跳过 npm/CDN/install.sh 的全网探测（那些结论对用户可见产出无影响，仅写入文档作防坑记录）。

**仍未解决**：官方 CLI 独立发行包下载根地址未公开（对用户无影响，源码构建可用）；CDN dmg 与 GitHub Release 资产 sha256 不一致的原因（重打包/签名时间戳，未深究，已有 codesign 兜底）。

**经验沉淀**：npm `zcode` 占位包 + 假 install.sh 域名 → 已录 ~/.dsh/LESSONS.md（编号 E208）；本文件即本工单常驻记录，工具本体在 ~/.local/zcode-src 与 ~/.local/bin/zcode（勿删，重装方法见本文档第二节）。
