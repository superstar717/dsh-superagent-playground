# 局域网手机↔电脑传文件：GitHub 开源工具调研（2026-11-23）

> 抓取时间：2026-11-23 02:2x–02:5x CST。数据来源：GitHub REST API（`gh api repos/...`、`search/repositories`、`security-advisories`）、各仓库 README 与 release notes。星标/推送时间会继续变化，下表均为抓取时点快照。

## 一句话结论

**有，而且选择很多。** 默认首选 **LocalSend**（跨 5 平台、纯局域网、100k★、Apache-2.0）；**敏感文件或没有路由器**用 **FlyingCarpet**（一次性密码 + Noise 加密，热点直连）；**不想装 App** 用 **PairDrop**（双方浏览器）或 **DashBeam 网页端**；**要通知/剪贴板联动**用 **KDE Connect**；**长期同步文件夹**用 **Syncthing**。注意：LocalSend ≤1.17.0 有已公开的严重 MitM 漏洞，务必用 **1.18+**。

## 按场景推荐

| 场景 | 推荐 | 理由 |
|---|---|---|

| 敏感文件 / 出差只有热点、无路由器 | **FlyingCarpet** | 共享网络或热点直连；一次性密码 + Noise 加密；跨 5 平台 |

| 长期同步相册/工作目录（非一次性） | **Syncthing** | 持续双向同步；90k★；Android 官方 App 已归档，需社区 Fork |

## 安全与隐私注意

### 1) LocalSend：旧版有严重漏洞，务必 1.18+

- **CVE-2025-54792 / GHSA-424h-5f6m-x63f（critical，2025-08-01）**：UDP 设备发现无认证，同网攻击者可伪造源 IP、冒充设备，静默截获/篡改传输文件。公告至今仍写 vulnerable `<= 1.17.0`、`patched_versions` 为空。
- **CVE-2025-27142（high，2025-02-25）**：上传接口路径穿越，≤1.16.1 可被附近设备写任意文件进而执行命令；已在 **1.17.0** 修复。
- **CVE-2026-25154（medium，2026-01-30）**：Web Share（分享链接）页面文件名存储型 XSS，影响 ≤1.17.0。
- 维护者在 issue #3135（2026-08-24 关闭）回复：**自 1.18.0 起启用 mTLS 并双向校验证书**（1.18.0 同时把核心网络层重写为 Rust）；v1.18.2 另修了「不跟随对端 HTTP 重定向」。
- 但公告没有标注修复版本，社区分析也指出仍可能接受 HTTP 回退的对端（降级风险）。**结论：用 1.18.2+；在同一 Wi-Fi 上核对设备别名与 IP；敏感文件改用 FlyingCarpet/DashBeam，或至少避免在不可信网络传敏感内容。**
- **1.18.0 起「收藏设备自动接收」默认开启**（release notes）。不需要就关掉：自动接收等于跳过人工确认。

### 2) 只在可信网络使用

访客 Wi-Fi、公司网、酒店网常有 **AP 隔离**（客户端互不可见）或禁止 mDNS/UDP 组播，工具会「搜不到设备」；反过来，同一公共网络里的陌生人也可能看到你的设备。跨网段/VPN 场景优先用支持中继或热点直连的工具。

### 3) 接收端必须确认，慎用自动接收

- LocalSend 有 PIN 校验选项；接收前核对设备名与 IP。
- FlyingCarpet 每次传输生成一次性密码（二维码），用完即弃。
- DashBeam 的「受信设备自动接收」是显式 opt-in，不要给不熟悉的设备开。
- PairDrop 需要接收端接受请求，但完成后会自动下载。

### 4) 明文与降级风险

- **qrcp 默认 HTTP**（`secure=false`），仅可信局域网；需要加密时配 `--secure` + 证书。
- **LocalSend** 正常情况下走 HTTPS，但存在接受 HTTP 对端的可能（见上）。
- **croc** 是 PAKE 端到端加密，优先 P2P 直连、打洞失败才走公共 relay（可 `--relay` 自建）；纯局域网且在意传输路径时优先 FlyingCarpet/DashBeam/LocalSend。
- **PairDrop/Snapdrop** 走 WebRTC（DTLS），信令经公共服务器；自建实例更可控。

### 5) 临时 HTTP 服务用完即关

dufs / miniserve / qrcp 这类「电脑开个服务，手机浏览器访问」的方案：只监听内网、设置认证、必要时上 HTTPS，传完立即停止；**永远不要把端口映射到公网**。

### 6) 公共网页互传实例的隐私面

pairdrop.net 这类公共实例默认展示「同一本地网络 / 同一临时公共房间 / 已配对」的设备，**同一公共房间里所有设备互相可见**；敏感文件建议自建实例或改用 App 方案。

### 7) 便利功能的隐私面

KDE Connect 的剪贴板同步、通知同步会把内容带到另一端；Syncthing 是整目录持续同步（删改都会同步），别把含密钥/隐私的目录随手共享。

### 8) 安装来源与更新

- LocalSend 没有自动更新（README 明确建议从应用商店/包管理器安装）；从官方 release / 商店安装，核对签名与校验和。
- 所有工具都优先用最新版：本文抓取时点 LocalSend 已到 1.18.2，1.17 及更早不要再用于敏感文件。

### 9) 已停更/已归档，不要新用

- **File Browser**：2026-09-01 归档。README 明确「不再有 release、bug 修复或安全修复」，并列出两类未修问题：命令执行/runner/hooks 漏洞群、JWT 会话不可撤销（登出/改密后旧 token 仍有效）。若已部署：别暴露公网、保持 runner 关闭、容器内非特权运行。
- **LANDrop**：最新 release 仍是 2021 年的 v0.4.0，2024-08 后无推送。
- **Snapdrop**：主仓 2025-02 后无提交；用 PairDrop 替代（注意 PairDrop 本身也放缓）。
- **Warpinator**：本体活跃，但 Windows/iOS 端多为第三方移植，跨平台体验不如 LocalSend。

## 复现与数据口径

```bash
# 星标/推送/许可证
gh api repos/localsend/localsend --jq '{stars:.stargazers_count,pushed:.pushed_at,license:.license.spdx_id}'
# 最新 release
gh api repos/localsend/localsend/releases/latest --jq '{tag:.tag_name,published:.published_at}'
# 安全公告
gh api repos/localsend/localsend/security-advisories \
  --jq '.[] | [.ghsa_id,.severity,.published_at,.summary] | @tsv'
# 关键词搜项目
gh api -X GET search/repositories -f q="airdrop alternative" -f sort=stars -f per_page=10 \
  --jq '.items[] | [.full_name,.stargazers_count,.pushed_at] | @tsv'
```

口径说明：
- 「活跃」按最近 push 与最新 release 综合判断，不代表代码质量。
- 星标只作热度参考；KDE Connect 这类经发行版分发的项目星标明显低估实际用户量。
- LocalSend 漏洞修复状态以 GitHub Security Advisory 与维护者 issue 回复为准；公告未更新 patched 版本，故本文同时给出「1.18 起 mTLS」与「公告仍标 <=1.17.0」两方信息，不替官方下结论。
